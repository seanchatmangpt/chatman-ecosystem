# Appendix L — Exact-Head GitHub Publication Protocol

GitHub is a publication and collaboration substrate. It is not the sole source of runtime truth.

## Protocol

1. Resolve the repository and base branch to an exact commit SHA.
2. Preserve the base identity; do not silently move it during the task.
3. Read root and applicable nested doctrine.
4. Inspect the exact files and owning generators before editing.
5. Create a purpose branch from the admitted base.
6. Make the smallest coherent diff.
7. Run the narrowest high-information local validators available.
8. Run repository-mandated crown or release checks when the environment supports them.
9. Commit intentionally.
10. Push or update the branch without force unless explicitly required and authorized.
11. Open a **draft PR** by default.
12. Resolve the PR head to its exact SHA.
13. Inspect CI for that exact head; stale-head results do not crown the new subject.
14. Record branch, commit, PR, commands, exits, failures, and remaining falsifiers.

## Status discipline

`workflow exists` is not `workflow ran`.

`workflow ran` is not `workflow succeeded`.

`workflow succeeded` is not automatically `SUBJECT_ALIVE` unless the workflow satisfies the declared acceptance claim.

## Merge

Merge is a separate DO operation and requires explicit scope authority.
