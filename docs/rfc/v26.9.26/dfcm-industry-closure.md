# RFC v26.9.26 — DfCM Industry Closure: Chatman/Fuller Architecture

## Normative claim

Subject to an explicitly declared common boundary, **Chatman/Fuller v26.9.26 is the best architecture until falsified by a strictly superior architecture under the same court**.

This is an architecture-level claim about the relationship among reality, knowledge, possibility, manufacture, authority, consequence, evidence, learning and replacement. It is not a claim that every implementation is already enumerated.

The canonical path is:

```text
Reality
-> Observe
-> Admit
-> DfCM
-> Reuse / Compose / Extend / Invent
-> Falsify
-> Verify
-> Formalize
-> Manufacture
-> Authorize
-> DO
-> Receipt
-> Replay
-> Retire
```

## DfCM

Design for Combinatorial Maximalism preserves the maximum **useful, lawful, reversible possibility space** before irreversible selection.

```text
Bound = Ontology ∩ Capability ∩ Authority ∩ Cost ∩ Evidence ∩ Consequence
```

Human comprehension is not the system boundary. Human authority and human computation remain distinct.

## Falsifier

For a versioned Chatman/Fuller subject `C_v`, produce an admissible competing architecture `X` under the exact same subject class, boundary, workload, constraints, authority, evidence requirements, costs and consequences such that `X` is no worse on every required dimension and strictly better on at least one.

If `X ≻ C_v`, that version is falsified.

Assimilation into `C_(v+1)` does not erase the defeat of `C_v`.

## Pacemaker court

Safety-critical comparison is not “AI programmer vs human programmer.” It is artisanal artifact vs evidence-bearing manufactured artifact. The stronger the consequence, the stronger the court.

Correctness and standing must be bound through:

```text
requirements -> hazards -> admission -> specification -> manufacture
-> independent verification -> authority -> actuation -> receipt -> replay
```

Qualification is evidence. Qualification is not authority.

## Component boundary

A better planner, verifier, database, AI, strategic operator, generator, ontology or vendor SBB does not by itself defeat the architecture. It is a candidate component.

A defeating architecture must improve the reality-to-consequence relationship itself.

## Industry projection

Within an industry boundary, downstream ABB/SBB resolution follows:

```text
Requirement -> Reuse | Compose | Extend | Invent | REFUSED(type)
```

ABB/SBB coverage is therefore a downstream closure test, not the definition of Industry Closure itself.

## Strategic operators

Berthier and the 33 Strategies are replaceable strategic machinery inside Chatman/Fuller. They may expand and coordinate the DfCM strategic frontier, but neither planning nor strategy confers authority.

```text
OBSERVE != SELECT != CONSTRUCT != DO
candidate != truth != authority != standing
```

## Governing law

```text
Find -> Fence -> Reuse/Compose -> Falsify -> Verify -> Formalize
-> Automate -> Receipt -> Replay -> Retire
```

Successful intelligence lowers the intelligence required next time.

The permanent architecture test is:

> Can you build a better architecture under the same court?

If yes, this version loses. If no admissible challenger does, this version retains standing.
