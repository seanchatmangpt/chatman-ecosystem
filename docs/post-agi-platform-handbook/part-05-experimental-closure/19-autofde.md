# 19. AutoFDE as Reality Acquisition

The Forward Deployed Engineer is a human organizational solution to an epistemic problem: a product or platform does not yet understand the customer's real environment well enough to operate there.

AutoFDE generalizes the function rather than the job title.

\[
Unknown\ Reality \rightarrow Admitted\ Machine\text{-}Operable\ Model
\]

## Discovery before solution

A post-AGI AutoFDE loop begins by acquiring reality:

\[
O \rightarrow Discover \rightarrow Graph \rightarrow Admit \rightarrow O^*
\]

Only then does it manufacture candidate interventions.

This prevents the common failure mode in which an agent recognizes a familiar problem shape and applies a known solution before proving that the target environment belongs to the same class.

## Reality acquisition is multimodal and multi-interface

Relevant observations may come from repositories, cloud APIs, schemas, event histories, tickets, calendars, documents, CI, telemetry, process models, human interviews, and physical sensors.

The acquisition system should preserve provenance and distinguish direct observation from semantic inference.

The result is not a pile of connector outputs. It is an aligned graph with explicit gaps.

## From FDE to epistemology

The human FDE historically performed four hidden functions:

1. discover what the customer actually has;
2. translate local language into product concepts;
3. identify a viable intervention;
4. bridge the intervention into the customer's operational reality.

AutoFDE makes those transformations explicit and receiptable.

When the class is solved, future deployments should use class closure rather than repeating bespoke discovery from zero.

## GymAct before production

The acquired model can manufacture a synthetic environment for experimentation. Candidate integrations run against that environment before operational admission.

This turns field deployment into a scientific loop:

\[
Observe \rightarrow Model \rightarrow Construct \rightarrow Experiment \rightarrow Evidence \rightarrow Actuate \rightarrow Observe'
\]

## Public ontology reduces onboarding cost

When the target environment uses public semantic vocabularies, the acquisition system inherits prior meaning. Custom ontology is needed only for genuinely local concepts.

This is one reason public ontology acts as civilization memory: it reduces the semantic distance between previously unseen environments.

## Falsifier

AutoFDE has not acquired the environment if its model can only explain the target through product-specific labels while failing to preserve the target's own material constraints and identities.

## Operational exercise

Choose a new environment you have never integrated. Define an observation plan that produces a graph without proposing a solution. Only after the graph contains explicit identities, constraints, evidence, and unknowns should the system construct integration candidates.
