# QME-1 Adoption

Consumers reference the canonical QME-1 specification rather than copying it. Adoption sequence: inventory private semantics; bind canonical owners; declare exact subject and evidence horizon; classify authority and consequence; import negative knowledge with boundaries and falsifiers; add independent observation; make replay non-actuating; add compatibility aliases; prove parity; retire duplicates.

A consumer is not conformant merely because it emits a receipt. Receipt, evidence, policy, plan and signature remain distinct from authority and standing.


## Absorption loop

Universal adoption does not require adoption of the reference stack. A foreign capability SHOULD enter through:

`candidate -> semantic extraction -> canonical owner -> inherited QME courts -> local projection -> exact-subject receipt`.

Before replacing mature prior art, the adopter SHOULD reconstruct the negative knowledge encoded by its constraints. This is the Reverse-Chesterton rule: replacement requires a falsifier showing that the existing constraint no longer serves its originating function for the same subject and boundary.

A successful import should therefore reduce future novel implementation work. If adoption creates private semantics, duplicate authority paths, unverifiable state or repeated model reasoning without durable qualified machinery, its net QME value may be zero or negative.

## Fleet reconciliation loop

A live repository is an observation source, not an authority source. Fleet updates therefore use:

`repo@exact-head -> OBSERVED -> QME qualification -> O* -> manufacture -> receipt`.

Moving a branch never rewrites an earlier receipt. The new head is re-observed and re-qualified. Cross-repository composition may add capability while `projection_authority_effect` remains `NONE`; authority must still arrive through the separately admitted consequential boundary.
