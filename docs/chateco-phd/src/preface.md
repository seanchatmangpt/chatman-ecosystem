# Preface: From Plausibility to Standing

Software generation has become cheap enough that production volume can no longer serve as a proxy for correctness. A system may emit code, plans, proofs, workflows, cloud manifests, policies, and documents faster than any human organization can inspect them. That changes the binding constraint. The scarce resource is not candidate production; it is defensible standing.

Chateco is organized around that inversion. Generation belongs to CONSTRUCT. Consequence belongs to DO. Between them sit admission, verification, authority, and the receipt boundary. The wider the reversible design space becomes, the more important it is that irreversible reachability remain narrow. Design for Combinatorial Maximalism and BRCE are therefore complements rather than competitors: one expands lawful possibility while the other restricts consequential power.

This manuscript should be read as a research program, not a declaration of universal victory. A local proof does not crown an ecosystem. A successful workflow does not prove the ontology. A green CI badge does not prove production consequence. A named receipt is not a receipt unless it binds exact identity, authority, execution, consequence, and replay. The text is strongest where it makes those distinctions mechanically testable and weakest where independent reproduction is still missing.
