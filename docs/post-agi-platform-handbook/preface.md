# Preface: After Platform Engineering

In 2026, a competent platform-engineering handbook could reasonably begin with source control, proceed through Kubernetes and service mesh, add identity and observability, introduce a developer portal, expose self-service onboarding and CI/CD, publish starter kits, enforce policy, optimize cost, automate resilience, and finish with AI-augmented workflows.

Nothing about that sequence was foolish. It was optimized for a world in which humans were the scarce routing, interpretation, and coordination layer.

The post-AGI handbook keeps the functions and discards the accidental hierarchy.

Source control exists because identity, provenance, collaboration, and replay matter. Kubernetes exists because scheduling, isolation, reconciliation, and declarative state matter. Developer portals exist because discoverability and bounded self-service matter. CI exists because repeated validation matters. Policy exists because not every constructible state is admissible. Observability exists because execution must produce evidence. FinOps exists because resources are bounded. Resilience exists because worlds diverge from plans. AI assistants exist because translation and construction are expensive for humans.

A post-AGI system still needs those functions. It does not need to preserve every human-shaped representation that once implemented them.

The central move of this book is therefore not automation. It is **factorization**.

We factor semantic truth from projection, possibility from selection, construction from actuation, execution from standing, and evidence from narrative. Once those distinctions are preserved, software systems can be manufactured at machine scale without turning generative capacity into ambient authority.

The result is not a better internal developer platform. It is an operating constitution for intelligence that can manufacture computational worlds.
