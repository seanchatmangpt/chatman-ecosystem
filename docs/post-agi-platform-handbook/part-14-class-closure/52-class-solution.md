# 52. From Instance Solution to Class Solution

A post-AGI civilization wastes intelligence if every new instance of a known problem must be solved from first principles.

The objective is class closure.

## Instance versus class

An instance solution says:

> This exact subject worked under this exact evidence.

A class solution says:

> Subjects satisfying these admitted equivalence conditions can be manufactured and verified by this reusable law.

The second claim is much stronger and therefore requires stronger evidence.

## Equivalence before analogy

Two systems that look similar are not automatically members of the same solved class.

The ecosystem requires an explicit equivalence relation over the properties that matter to the construction:

\[
x \sim_c y
\]

Only then can standing transfer through a parameterized construction.

This prevents analogy from masquerading as proof.

## Parameterized manufacture

A closed class has a manufacturing law that accepts the varying parameters while preserving the class invariants.

\[
\mu_c(p,O^*) \rightarrow A_p
\]

The verifier knows which obligations remain invariant and which must be re-executed for each subject.

## Historical standing becomes a prior

Prior successful instances supply evidence that the class law is useful. They do not eliminate exact-subject verification where runtime behavior can vary.

Class closure therefore reduces repeated reasoning without erasing reality.

## Reopening a class

A class can be superseded or reopened when a falsifier appears: a new substrate violates an assumed invariant, a provider changes behavior, a proof obligation was incomplete, or a failure instance disproves transfer.

Civilization memory must preserve revision history rather than treating closure as eternal truth.

## Falsifier

A claimed class closure is invalid if a new instance can satisfy the declared class predicate while violating an invariant required by the manufacturing law.

## Operational exercise

Take three similar services or repositories. Define the equivalence relation that would justify using one ggen pack for all three. Then search specifically for a counterexample that belongs to the class syntactically but not semantically.
