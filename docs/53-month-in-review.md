# The Month the Factory Became a Control System

The most important development of the July 15–August 15 period was not any single feature. It was the repeated conversion of **local engineering pain into reusable production law**.

The ecosystem increasingly stopped behaving like a collection of projects that happened to share ideas and started behaving like a factory that can inspect, admit, manufacture, execute, receipt, replay, and govern the projects themselves.

## From local fixes to poka-yoke

Several gym consumers independently exposed the same class of ggen integration defect: malformed consumer manifests, missing required template configuration, pack templates rendered twice because consumer and pack template roots were conflated, invalid gate placement, or relative paths resolved against the wrong boundary.

The important response was not merely repairing each repository. The repeated failure was treated as evidence that the **production system** was defective. The marketplace then gained consumer-side scaffolding and admission rules so the class becomes harder to reproduce.

That is the factory learning loop:

```text
observed defect
    -> exact failure identity
    -> root cause
    -> reusable exclusion / standard work
    -> deterministic scaffold or gate
    -> qualification
    -> future defect becomes structurally inadmissible
```

The same pattern appeared in cross-pack references. A warning-only lint first exposed real dangling or unqualified cross-pack relationships. Existing violations were repaired. Only after the corpus was clean did the lint become a hard gate. The system therefore moved from detection to prevention without rewriting history or pretending the inherited debt never existed.

## DfCM became executable

DfCM matured from an architectural preference into real option-space machinery. One executed frontier combined 190 candidate gyms with 57 planner identities:

\[
190 \times 57 = 10{,}830
\]

reversible planner×gym edges.

Refusing one edge preserved the other 10,829 rather than collapsing the graph. That is the key operational meaning of Combinatorial Maximalism: a failed edge is topology, not graph failure.

Process-intelligence work independently demonstrated large candidate spaces being admitted, refused, and deterministically selected under explicit constraints. The result is a stronger replacement for “ask an agent what to do”: first manufacture the lawful space; then select only when a selection boundary is actually required.

## MCP moved toward generated deterministic protocol law

The gdmcp work shifted MCP from “a convenient agent tool protocol” toward an ontology-first deterministic transport surface. The protocol revision, feature set, language projections, consequence classification, transport semantics, and authorization overlay can be manufactured from canonical graph state.

The constitutional consequence is more important than SDK coverage:

\[
\boxed{\text{MCP transport} \neq \text{reasoning} \neq \text{authority}}
\]

An MCP server can expose a consequential operation without being able to grant itself permission to perform that operation. The same GymAct/BRCE boundary still applies.

## Planning became a first-class plane

AutoFDE-Lab, POWL, mmdio, and related work increasingly separated formal planning semantics from documentation, orchestration, and execution. Native PDDL/PPDDL/PDDL+/RDDL/POWL semantics can be projected into canonical planning graphs and then into human-readable diagrams without making Mermaid the semantic authority.

POWL gained a receipted partial-order execution model with concurrency, leases, stale-worker fencing, and explicit handling of uncertain external consequences. A critical operational rule emerged:

\[
\boxed{\text{unknown external consequence} \not\Rightarrow \text{blind retry}}
\]

This is the kind of rule required when workflows leave the toy domain and begin coordinating consequential systems.

## Process intelligence gained Definition of Done

A major advance was the explicit separation of **ALIVE** from **DONE**. A capability can execute correctly while the project that depends on it still has unresolved integration, replay, lifecycle, or release obligations.

Executable Definition-of-Done work composed capability evidence, DfCM evidence, replay, exact-subject binding, and release predicates. The same idea was then extended upward into enterprise lifecycle law: a target implementation can be working while legacy retirement, transition architectures, operational ownership, baseline registration, or change governance remain open.

Therefore:

\[
\boxed{\text{ALIVE} \neq \text{PROJECT CLOSED}}
\]

## WIP became an observable system object

The Little’s Law WIP scanner line moved repository activity toward a typed WIP graph. Issues, PRs, branches, CI, dependency blockers, source markers, tests, documentation, and release obligations can be collapsed into logical WIP objects rather than counted as unrelated UI artifacts.

That makes the classical relationship operationally useful:

\[
L = \lambda W
\]

without pretending that every observed period is steady state. The important output is not a vanity metric; it is a closure frontier: which reversible actions eliminate the most admitted WIP and unblock the most downstream work?

ERRC then becomes executable prioritization:

- **ELIMINATE** obsolete, duplicate, orphaned, or generated-only WIP;
- **REDUCE** unnecessary code, tests, review, stale PRs, unsatisfied requirements, and source markers;
- **RAISE** CI, dependency, replay, and cross-repo quality where they constrain flow;
- **CREATE** only closure artifacts that retire existing admitted WIP.

## Old prototypes became option value

Another meaningful shift was the treatment of old repositories and dormant branches. The default ceased to be “merge it because it exists” or “discard it because it is old.” Reconciliation work demonstrated a third path: recover the still-valid semantic delta and transplant it onto the current admitted base.

That creates a more useful classification for old work:

```text
falsified
obsolete
dependency-blocked
toolchain-blocked
model-capability-blocked
still viable
```

A large historical portfolio can then become searchable evidence rather than an undifferentiated maintenance burden.

## Exact-subject evidence became normal

Across the month, PR descriptions and workflows increasingly bound claims to exact repository/ref/SHA identities, exact execution runs, negative falsifiers, generated-status boundaries, and replay surfaces. Equally important, infrastructure failures were typed rather than misreported as source failures: local DNS, CI runner allocation, private cross-repository token scope, missing dependency closure, and stale generated projections remained distinct states.

This is constitutional progress because it reduces the number of ways a plausible story can masquerade as observed execution.

## The month’s architectural fixed point

The emerging factory can be compressed as:

```text
public ontology
    -> canonical graph
    -> ggen / marketplace manufacture
    -> formal + mechanical admission
    -> AutoFDE / POWL SELECT + CONSTRUCT
    -> GymAct / BRCE DO
    -> receipts + OCEL replay
    -> process intelligence
    -> WIP / lifecycle / release closure
```

The next transition is not simply to accelerate this pipeline. It is to remove the human operator from **normal scheduling**. When dependency state, evidence state, WIP impact, and release obligations can pull the next lawful work item automatically, commit rate stops being the primary target. The better measures become closure throughput, cycle time, escaped defect classes, receipts per consequential transition, and operator touches per completed closure.
