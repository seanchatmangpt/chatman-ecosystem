# Development and Verification Guide

## Development law

Read `AGENTS.md` and `CONSTITUTION.md` before changing cross-cutting behavior. Treat canonical TOML/source as authoritative and generated Markdown as a projection.

The default engineering loop is:

```text
inspect -> admit plan -> implement -> narrow verify -> repair -> expand verify -> publish draft -> exact-head CI
```

## Workspace layers

### Rust constitutional/control-plane workspace

The dependency direction is:

```text
ecosystem-core
      ^
ecosystem-runtime
      ^
ecosystem-cli
```

Keep constitutional identity/standing/authority/receipt logic out of framework-specific adapter layers.

Useful commands:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --all-features --locked
cargo doc --workspace --no-deps --locked
```

The repository's integrated admission command remains:

```bash
./scripts/crown.sh
```

It may require repository-documented tooling such as `cargo-deny` and `cargo-machete`.

## Control-plane CLI checks

Useful focused commands include:

```bash
cargo run --locked -p ecosystem-cli --bin ecosystem -- catalog validate
cargo run --locked -p ecosystem-cli --bin ecosystem -- receipt verify-all
cargo run --locked -p ecosystem-cli --bin ecosystem -- projection check
cargo run --locked -p ecosystem-cli --bin ecosystem -- architecture check
cargo run --locked -p ecosystem-cli --bin ecosystem -- storage verify
cargo run --locked -p ecosystem-cli --bin ecosystem -- crown --verify
```

Run the narrowest relevant command during repair, then the integrated Crown before claiming repo-level `ALIVE`.

## Python service checks

The ggen/ggen-marketplace bridge contains Python service code. `py_compile` is syntax-only and previously missed a real `urllib.request.quote` runtime defect. Use both syntax and static/type validation where configured.

Representative checks:

```bash
python3 -m py_compile platform-console/services/ggen/app.py
python3 -m py_compile platform-console/services/ggen-marketplace/app.py
pyright platform-console/services/ggen/app.py platform-console/services/ggen-marketplace/app.py
```

Do not weaken type checks because syntax compilation is green.

## Platform-console TypeScript

The console has real server-side API and client UI behavior. At minimum:

```bash
cd platform-console/app
npm ci
npx tsc --noEmit
```

Where Playwright/E2E is available, use the repo's existing E2E command against a real admitted deployment rather than replacing it with mocked auth or synthetic APIs.

A browser 200 is not enough for mutation paths: verify Kubernetes/service postconditions too.

## Kubernetes manifests

Validate syntax before live apply, but distinguish parse from admission and admission from runtime:

```text
YAML parses
< API server admits
< controller creates resources
< pods become Ready
< capability behaves correctly
< consequence matches requested intent
```

Use `kubectl diff` against the intended context where available. Always name the cluster/context in evidence when a live claim depends on it.

## Documentation

The mdBook source root is `docs/`; `docs/SUMMARY.md` is the publication graph.

Local docs gate when mdBook is available:

```bash
mdbook build
```

Documentation changes should also verify:

- every current cross-cutting doc is registered as needed in `catalog/documents.toml`;
- new mdBook pages are linked in `docs/SUMMARY.md`;
- historical evidence is not rewritten as current;
- generated projections are untouched or regenerated by their owner;
- v26.8.18/v26.9.1 currentness is explicit.

See `DOCS-MAINTENANCE.md`.

## Release verifier

For the future dependency-closed composition:

```bash
python3 scripts/verify_release.py
python3 scripts/verify_release.py --check-refs
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Use `--require-alive` only when testing the strict Crown condition.

## Negative fixtures

Negative behavior is first-class. Do not delete or skip a refusal fixture to make CI green. Preserve tests for:

- malformed/stale identity;
- unauthorized mutation;
- duplicate/idempotent execution;
- receipt tampering;
- undeclared capability/import;
- projection drift;
- incompatible architecture dependency;
- network/tenant boundary violations;
- unavailable real dependency returning explicit failure.

## Failure classification

| Observation | State |
|---|---|
| not inspected/executed | `UNKNOWN` |
| some required edges verified | `PARTIAL_ALIVE` |
| all required exact-subject edges executed/verified/receipted | `ALIVE` |
| external prerequisite missing | `BLOCKED` |
| attempted build/test failed | `BUILD_BROKEN` |
| mechanism not implemented/supported | `UNSUPPORTED` |
| transition correctly rejected | typed `REFUSED` |

Do not translate `UNSUPPORTED` into `REFUSED`, or `UNKNOWN` into `ALIVE`.

## Dependency changes

Prefer existing dependencies and patterns. A dependency is justified when it closes a required capability more safely or deterministically than local code. Preserve the constitutional core's framework-independence gate.

## Generated artifacts

Never edit generated docs/status merely to satisfy a diff. Fix canonical source or generator, regenerate, and verify no drift. If the toolchain to regenerate is unavailable, report the generated artifact as stale rather than forging synchronization.

## Commit discipline

Use a purpose branch, intentional scope, and coherent commits. Avoid accidental credential/key inclusion. The repo already had an incident where generated ggen signing material was accidentally added; `.ggen/` and `.ggen-v2/` are ignored to prevent recurrence.

Before publication, inspect the final diff for:

- secrets/private keys;
- generated output edited manually;
- unrelated refactors;
- stale version assertions;
- weakened tests;
- invented evidence.

## Acceptance hierarchy

When the user names an acceptance command, run that exact command if the environment supports it. Otherwise use the documented repository command, then the narrowest existing verifier. Never substitute a unit test for a requested live integration/e2e consequence without classifying the gap.
