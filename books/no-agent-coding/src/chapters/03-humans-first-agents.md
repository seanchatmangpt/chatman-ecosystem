# 3. Humans Were the First Coding Agents

**Executive thesis:** The term agent should describe a role in a system, not a species. Human programmers were the original context-consuming, tool-using, state-changing coding agents.

## A neutral definition

An agent observes a partial environment, selects actions under incomplete knowledge, uses tools, and changes state. Human engineers fit that description. They bring judgment, accountability, creativity, and social understanding, but for known repeatable work they also carry variable context, handoffs, memory loss, onboarding cost, and irreproducible reasoning.

## Do not insult the frontier

Calling humans agents is not an argument for removing people. It is an argument for reserving people for work worthy of people. When a known rule is executed manually for the thousandth time, the organization is consuming scarce judgment as a runtime dependency. The same is true when an LLM is asked to rediscover that rule on every invocation.

## The economic flip

The conventional AI metric asks how many tasks an agent can perform. No Agent Coding asks how many recurring task classes no longer require an agent. That converts intelligence from rent into capital. Discovery is paid for once; the discovered law is encoded; subsequent instances are manufactured or refused deterministically.

## Operating practice

Inventory recurring engineering decisions: routing, project topology, schema projection, policy checks, deployment shapes, documentation synchronization, evidence packaging. For each, ask whether a bounded contract can replace interpretation. Agent retirement means retiring repeated cognition from a class of work, not retiring the humans who discovered and govern the class.

## Diagnostic question

Which expert queues exist mainly because known decisions still require a human runtime?
