# No Agent Coding: Building the Deterministic Enterprise

Software engineering is entering a phase in which producing another plausible implementation is no longer the scarce capability. Human programmers have always interpreted incomplete intent probabilistically. Vibe coding moved that same interpretive architecture into large language models. Agentic coding added tools, memory, loops, and actuation. Each step increased the rate at which candidate work can be produced.

This book argues that the next step is not a still more autonomous coding agent. It is **No Agent Coding**: use human and machine intelligence to discover novelty, then compile stable knowledge into an admitted deterministic substrate so known work no longer requires repeated interpretation.

The central transform is:

```text
O  →  admission  →  O*  →  μ  →  A  →  receipt  →  replay  →  standing
```

`O` is observation or conjecture. `O*` is bounded admitted observation. `μ` is lawful manufacture. `A` is a projection: code, schema, API, workflow, policy, cloud resource, documentation, marketplace package, or another artifact. A receipt binds exact subject, authority, consequence, and replay evidence.

The argument combines two traditions. From pragmatic software engineering it takes the discipline of eliminating duplicated knowledge, preserving orthogonality, using end-to-end tracer bullets, designing contracts, and refusing broken windows. From enterprise architecture strategy it takes the operating-model question: what must be integrated, what must be standardized, and what foundation lets the enterprise execute repeatedly without renegotiating itself. The Chatman Ecosystem and especially ggen provide the manufacturing interpretation of those ideas.

The book is intentionally a challenger text. It does not ask whether humans or models are better programmers. It asks why the enterprise keeps paying any agent to rediscover decisions it already knows. Rice’s theorem supplies the epistemic boundary, Chesterton’s Fence the preservation rule, Gall’s Law the growth rule, Little’s Law the flow rule, Conway’s Law the organizational topology rule, and DfCM the search geometry. ggen is the deterministic manufacturing response implied by that combination.

The managerial goal is simple to state and hard to fake:

> **Use intelligence to discover the law. Do not use intelligence to reenact the law forever.**

This is not an argument for zero humans, zero AI, or zero code. It is an argument for intelligence at the frontier and determinism in the core.
