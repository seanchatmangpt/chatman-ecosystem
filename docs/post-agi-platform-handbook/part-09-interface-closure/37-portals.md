# 37. Developer Portals After Developers

Developer portals such as Backstage solved a real problem: platform capabilities were fragmented across systems and humans needed one discoverable surface.

The function survives post-AGI. The human-centric portal no longer needs to be the semantic center.

## Portal as projection

Catalog entries, forms, templates, documentation, ownership views, and actions can be generated from the same capability graph that produces machine interfaces.

\[
Graph \rightarrow Portal
\]

The portal is therefore one view of platform knowledge.

## Humans become one consumer class

Human users still matter. They may require explanations, approvals, exceptions, and visual evidence. But the platform should not force machine consumers to scrape or imitate a human portal to access capabilities.

Machines get native semantic interfaces. Humans get interfaces optimized for human cognition.

## Starter kits become class instances

A historical portal may offer a fixed set of project templates. In DfCM, those templates become high-standing class instances or priors.

A user can still choose “standard service,” but the system can manufacture a bounded variant when the request differs along admitted dimensions.

The portal is selecting from a construction space rather than launching a rigid script.

## Self-service becomes self-manufacture

The original promise of self-service was that developers could obtain approved infrastructure without opening tickets.

The post-AGI promise is stronger: a consumer can state an admitted outcome, and the system can construct a lawful implementation from the semantic graph.

The UI may still look like a form. The underlying abstraction has changed from catalog lookup to bounded manufacture.

## Falsifier

A portal remains an architectural bottleneck if capabilities must be manually reimplemented in portal-specific code rather than projected from shared semantics.

## Operational exercise

Take one Backstage template and separate its business semantics from its UI form and scaffolding code. Move the semantics into a capability graph, then regenerate the human form and one machine interface from the same source.
