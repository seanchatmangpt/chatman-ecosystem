# RFC v26.9.25 — External Paradigm Recompilation

**Status:** Proposed implementation slice  
**Owner:** chatman-ecosystem  
**Reference supplier:** affaan-m/ECC @ `e482e579415fde18357cafce70f177ae19fd7f03`

## Problem

The ecosystem should not repeatedly purchase intelligence to rediscover
engineering patterns that active upstream communities already discover,
implement, test, and maintain.

A conventional fork is insufficient. A divergent fork converts upstream
innovation into local merge debt. Blind dependency consumption is also
insufficient because upstream semantics, authority models, verification
claims, and completion states do not automatically satisfy Chatman Ecosystem
laws.

## Decision

Introduce **External Paradigm Recompilation (EPR)**.

An external repository is an independently evolving candidate-pattern source.
The ecosystem pins an exact upstream subject, extracts pattern semantics,
classifies the delta, and manufactures an admitted local projection.

```text
U@sha
 -> observe
 -> extract
 -> normalize
 -> deduplicate
 -> {VENDOR | WRAP | REPLACE | NOVEL_GAP}
 -> falsify
 -> qualify
 -> manufacture
 -> admit
 -> expose as capability
 -> BRCE if consequential
 -> receipt
```

No step may silently promote upstream execution into local standing.

## Dispositions

### VENDOR

Use the upstream implementation substantially as maintained. The ecosystem
owns pinning, integrity, qualification, and integration boundaries, not the
supplier's internal implementation.

### WRAP

Preserve the upstream mechanism and surface while adding local semantics,
provenance, admission, authority, or receipts.

### REPLACE

Preserve the discovered pattern/problem formulation, but replace the
implementation/control semantics with stronger existing ecosystem machinery.
Examples include replacing prompt-planned orchestration with HDDL/FOND or
narrative verification with exact-subject GALL courts.

### NOVEL_GAP

Only this disposition authorizes local invention work. It requires an explicit
falsifier showing that the qualified external capability set cannot satisfy
the required semantics.

## ECC v1 mapping

ECC is the first supplier because it concentrates patterns from the broader
agent-harness ecosystem.

Initial mapping:

- cross-harness adapters -> VENDOR;
- AgentShield -> VENDOR, findings consumed as evidence;
- skills/agents/commands -> WRAP into candidate capabilities;
- continuous-learning observation -> keep, but promotion semantics -> REPLACE;
- autonomous-loop planning -> REPLACE with HDDL/FOND/sJira where applicable;
- verification-loop READY state -> REPLACE with GALL/receipt/replay;
- unified memory -> WRAP as provenance-bound observation, never authority;
- hooks -> WRAP as observation/interception, with BRCE as the sole
  consequential DO boundary.

The machine-readable mapping is `upstream/ecc/pattern-map.json`.

## Admission state

External suppliers begin as:

```text
CANDIDATE
```

not `ALIVE`.

A valid local registry proves only that the supplier subject and classification
metadata are structurally admissible for further qualification.

## Falsifiers

EPR v1 is falsified if any of the following is permitted:

1. a mutable upstream ref such as `main` is accepted as the supplier subject;
2. an upstream artifact self-grants `ALIVE` or consequential authority;
3. an ECC confidence score is treated as local admission;
4. an imported workflow performs consequential DO outside BRCE;
5. a supplier update is merged by hand without an exact-SHA delta;
6. generated local projections become canonical through manual editing;
7. duplicate local invention proceeds without a recorded `NOVEL_GAP`;
8. failure to retrieve a supplier is narrated as semantic refusal of its
   capability.

## Executable court

```bash
python3 scripts/verify_external_paradigms.py
python3 scripts/verify_external_paradigms.py --json
python3 -m unittest tests.test_external_paradigms -v
```

Success establishes only:

```text
registry metadata well formed
AND exact upstream subjects pinned
AND dispositions typed
AND supplier standing remains NONE
```

It does not establish that ECC was fetched, that any donor pattern was
qualified, generated, executed, or deployed.

## Next manufacture

The next slice should make the current static ECC pattern map generated:

1. fetch the pinned ECC tree;
2. enumerate durable units (skills, agents, commands, hooks, adapters);
3. project them into an RDF capability graph;
4. compare that graph with the admitted ecosystem capability graph;
5. emit classification candidates and semantic gaps;
6. send only unresolved equivalence/gap cases to higher-cost reasoning;
7. manufacture qualified mappings through ggen-marketplace.

The stopping direction is:

```text
new upstream paradigm
 -> machine classification
 -> existing formal machinery
 -> no exceptional reasoning
```

The success criterion is not the size of the fork. It is the declining amount
of new intelligence required to absorb the next upstream paradigm.
