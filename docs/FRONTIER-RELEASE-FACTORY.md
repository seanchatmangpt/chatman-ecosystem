# Frontier Release Factory

Status: **CANDIDATE control-plane protocol**. Canonical constraints live in `catalog/frontier-release-factory.toml`; this document is an explanatory projection.

## Purpose

The Frontier Release Factory turns public frontier announcements into executable comparison opportunities rather than recurring manual commentary.

```text
external release
  -> OBSERVE exact source
  -> EXTRACT normalized claim candidates
  -> FENCE system / boundary / prior art
  -> INVERT with DfCM
  -> SPECIFY working-backwards release + benchmark + falsifier
  -> CREATE REPOSITORY only when reuse/compose/extend cannot stay in an existing repo
  -> MANUFACTURE with ggen / ggen_igniter / owning framework generators
  -> VERIFY exact subject through the cheapest defensible ladder
  -> PUBLISH only the intersection of promised claims and ALIVE evidence
```

The factory is optimized for **verified externally relevant capability per unit of novel semantic reasoning purchased**, not for number of reactionary repositories or number of press releases.

## Two press releases

The working-backwards release is an acceptance target. It is allowed to describe what success would make true, but its status is `CANDIDATE`.

The earned release is manufactured after implementation and verification:

```text
EarnedClaims = WorkingBackwardsClaims ∩ AliveEvidenceClaims
```

Unsupported promises are omitted from the earned release and remain backlog/learning edges. A polished draft, source article, model output, green workflow definition, or generated artifact is not evidence for an earned claim.

No repository inherits another repository's standing merely because it consumes its output.

## Monitor without ambient authority

RSS, Atom, APIs, public release feeds and paper feeds can be monitored continuously under OBSERVE authority. The observation rail should retain source URL, publisher, publication time, source digest and raw claims/provenance.

Semantic extraction can use an LLM only for unresolved semantics. Its output remains a candidate. Known transforms route to deterministic parsers, RDF/SPARQL/SHACL, planners, solvers, process machinery, generators and formal verification.

A high-ranking opportunity still does not grant permission to create a repository or publish anything.

## DfCM inversion

For each external capability claim, the bounded response surface is considered in this order:

```text
reuse -> compose -> extend -> invent
```

Candidate transformations include replicate, benchmark, formalize, automate, commoditize and eliminate. A frontier lab's implementation shape is evidence that a capability can exist; it is not automatically the architecture the ecosystem should copy.

A failed implementation edge changes the opportunity graph. It does not imply that all alternative response modes failed.

## Repository creation

`gh repo create` is DO. It may occur only after the target-repository decision survives fencing and the authority broker admits the exact operation. Creation produces a receipt identifying the repository and the source opportunity that justified it.

The default is reuse or composition into an existing owner. New repository creation is a consequence of an admitted selection, not the first step of exploration.

## Manufacture

Known output forms must use their native manufacturer. Examples:

- semantic/software projections -> `ggen`;
- Ash/Igniter projects and extensions -> `ggen_igniter` plus framework generators;
- planning -> HDDL/PDDL/solver machinery;
- formal admission -> Lean/Lake/mfact where the claim is mathematical/formal;
- process intelligence -> Ex4pm;
- BEAM process projections -> Beam4pm.

Generated output remains a projection. If generation fails, repair canonical ontology/template/generator source rather than hand-editing the consequence.

## Verification and publication

Every working-backwards claim creates a proof obligation. The factory chooses the cheapest high-information verifier first, expands only after the narrow boundary passes, and records exact environment/toolchain identity when transfer matters.

Publication is a second DO edge. It requires explicit authority and a claim set already reduced to ALIVE evidence. Replay validates prior manufacture/actuation and must never create repositories, deploy, publish or otherwise reproduce DO side effects.

## Press-release positioning

The public comparison is not "our model is smarter." For each frontier announcement, the factory should report:

1. what the external source actually demonstrated;
2. the hidden infrastructure/cost/representation that enabled it;
3. which parts map to existing accumulated executable knowledge;
4. what was newly manufactured;
5. what exact benchmark was executed;
6. what remains blocked or unsupported;
7. the measured reduction, if any, in semantic recomputation, elapsed time, cost or exceptional-human dependence.

This allows large-lab announcements to function as continuously arriving external benchmark specifications.

## Falsifier

The architecture-level efficiency thesis is falsified for a bounded comparison if the factory cannot achieve independently replayable standing with less repeated semantic reconstruction than the baseline it claims to improve. The safety/authority thesis is falsified by any reachable unbrokered consequential transition that the contract claims is unreachable.
