# 54. The Marketplace as Executable Knowledge

A package registry distributes implementation. A post-AGI marketplace should distribute enough semantic and evidentiary structure to inherit a solved class.

The ggen marketplace is the natural projection of that idea.

## A pack is more than templates

A high-standing pack can contain:

- ontology imports and custom terms;
- semantic queries;
- deterministic projection templates;
- schemas and SHACL shapes;
- formal obligations;
- positive and negative fixtures;
- validation packs;
- GymAct world generators;
- interface projections;
- receipt expectations;
- class applicability conditions.

The concrete packaging format may evolve. The semantic bundle is the durable concept.

## Public plus custom ontology

A pack should declare which semantics come from public ontology and which are custom extensions.

That makes semantic debt visible and allows consumers to compose packs without inventing adapters for concepts that already share public meaning.

## Marketplace admission

A marketplace entry can exist at different standings. Presence is not endorsement.

A candidate pack may be useful for exploration. An ALIVE pack needs evidence for its declared gates and exact release subject.

Consumers can then choose based on required standing rather than assuming every downloadable package is equivalent.

## Packs close repeated work

When the same implementation pattern appears across repositories, the marketplace is where it should graduate from repeated human repair to deterministic manufacture.

This is the path from Kaizen to standard work at machine scale.

## Cross-language manufacture

Because the ontology sits above programming languages, a class can project into Rust, TypeScript, Python bindings, Terraform, Kubernetes, MCP, A2A, docs, and other targets without storing each projection as an independent product concept.

## Falsifier

A marketplace is only a template warehouse if consumers must reverse-engineer applicability, authority, negative behavior, and evidence requirements after installation.

Choose one repeated ecosystem pattern and specify the smallest marketplace pack that would let a new repository inherit it without bespoke human coordination. Include at least one public ontology import and one negative fixture.
