# 36. A2A and Inter-Intelligence Delegation

When multiple autonomous systems collaborate, the important problem is not chat. It is delegation with preserved identity, authority, evidence, and consequence.

A2A is therefore best understood as one projection for inter-intelligence capability exchange.

## Capability advertisements

An agent or service can advertise a capability profile containing:

- semantic capability identity;
- accepted input classes;
- produced artifact or evidence classes;
- supported authority modes;
- expected cost and latency;
- environment or locality constraints;
- historical standing;
- receipt requirements.

The advertisement is a claim and should carry its own provenance.

## Delegation is a morphism

Suppose intelligence `I_1` delegates a bounded task to `I_2`.

\[
I_1 \xrightarrow{delegate(s,a,scope)} I_2
\]

The delegation should not silently enlarge `scope`. `I_2` may have greater technical capability but receives only the authority attached to the delegated task.

## Evidence returns with the result

A useful machine delegation returns more than an answer. It returns the artifact plus evidence sufficient for the delegator to decide whether the result can advance.

This creates a machine economy of certified capabilities rather than a chain of uncheckable assertions.

## Delegation chains remain visible

If `I_2` delegates part of the work to `I_3`, the receipt graph should preserve the chain where it affects authority or evidence.

This is particularly important when different organizations or trust domains participate.

## Economic selection

DfCM can treat service selection as a constrained graph problem. The system may choose among providers based on evidence quality, ontology coverage, latency, cost, jurisdiction, capability, and authority requirements.

Price alone is not the objective.

## No universal super-agent required

Post-AGI architecture does not require one intelligence to possess every capability. A network of independently bounded systems can compose as long as semantic contracts, authority transfer, and receipts are explicit.

## Falsifier

Inter-intelligence delegation fails constitutional closure if the delegator cannot determine which exact subject was acted upon, who possessed authority, or what evidence supports the returned result.

## Operational exercise

Define a delegated build task with no shared implementation assumptions. Specify only ontology, exact inputs, output type, evidence obligations, authority class, and refusal semantics. Then test whether two different agents can satisfy the same contract.
