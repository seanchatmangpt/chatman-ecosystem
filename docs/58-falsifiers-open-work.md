# Falsifiers and Open Work

A system this broad is only useful if it states what would prove its claims wrong. The Chatman Ecosystem therefore treats falsifiers as design artifacts, not as adversarial commentary added after implementation.

## Constitutional falsifiers

The architecture should be reopened—not merely a component repaired—if a required lawful behavior cannot be represented without violating a frozen non-collapse law. Examples include evidence that:

- a consequential transition **must** occur without any representable authority boundary;
- a valid process **must** collapse SELECT, CONSTRUCT, and DO into one untyped operation;
- a receipt cannot bind enough identity to distinguish lawful from substituted consequence;
- public semantic state cannot be projected without making the projection canonical authority;
- an essential class of behavior cannot be expressed without ambient execution authority;
- the admitted object/morphism calculus is internally contradictory.

Ordinary implementation defects do not meet this bar.

## Manufacturing falsifiers

The ggen/manufacturing plane is falsified at a particular boundary if:

- identical admitted source produces non-deterministic outputs without an explicitly admitted nondeterministic relation;
- a generated projection becomes the only editable source of a semantic fact;
- query ordering or filesystem ordering changes consequences silently;
- pack qualification mutates canonical pack source;
- a consumer requires hand-recreating configuration that the pack contract claims to manufacture;
- an unsupported or unknown source format is silently promoted to decoded semantic truth.

## Planning falsifiers

The planning plane fails its role when:

- refusing one candidate erases unrelated reversible possibilities;
- a planner invents missing observations and reports them as known facts;
- empirical ranking advances without the payoff/evidence closure it claims to require;
- selected plans gain consequential authority merely because they are selected;
- a visualization or interchange carrier becomes more authoritative than the native formal semantics.

## Process falsifiers

The process/orchestration plane is falsified when:

- independent activities are serialized without causal reason and that serialization is treated as semantics;
- a stale worker can overwrite a sealed or newer transition;
- an unknown external consequence is blindly retried;
- lease expiry causes a healthy consequential operation to be duplicated;
- replay cannot distinguish an abandoned claim from a completed consequence;
- a workflow grants itself provider authority.

## Actuation falsifiers

The BRCE boundary fails if:

- a model, planner, hook, MCP request, role, policy, credential, or generated object can bypass independent authority admission;
- a consequential transition succeeds without a receipt;
- the receipt binds a different subject, policy, capability, or process than the one executed;
- postcondition verification is skipped but success is still crowned;
- a simulation can escape into a live port without an explicit new admission;
- receipt tampering survives verification.

## Evidence falsifiers

Evidence standing must be revoked when:

- exact subject identity drifts;
- a generated evidence projection is stale relative to its manufacturer;
- a prior receipt is attached to a new SHA by adjacency;
- inspection is represented as execution;
- workflow existence is represented as a successful run;
- an HTTP or CLI success code substitutes for required postcondition verification;
- an independently red required rail is hidden by a green aggregate summary.

## Current open classes of work

At the book base, the status graph still contains `BUILD_BROKEN`, `BLOCKED`, `UNKNOWN`, and `PARTIAL_ALIVE` required roles. This means the release is correctly non-crowned. The practical open work is not “make all repositories busy.” It is to close the minimum dependency frontier that blocks the required release graph.

Important classes include:

- role-specific exact-head execution for components that have partial evidence but no admitted crown receipt;
- repair of required CI gates that are actually source/build broken;
- removal of infrastructure execution blockers without relabeling them as source defects;
- exact dependency closure across private or branch-pinned components;
- convergence of generated evidence projections with their lawful manufacturers;
- replacement of recurring manual consumer setup with packs and admission gates;
- conversion of repo-by-repo scheduling into logical WIP pull;
- Pages enablement/publication for this book, independently of release standing.

## The extension rule

When a new requirement appears, apply the order:

```text
Preserve
 -> Chesterton/Fence
 -> Calculus: objects, morphisms, admission, closure, authority, actuation, receipt, replay
 -> Exclusions
 -> Falsifier
 -> Extension
 -> Operationalization
```

The point is to avoid expanding the constitution merely because a new tool or use case is unfamiliar. First determine whether the new object is already representable as an instance of an existing role.

## What would count as success

A mature ecosystem is not one with zero failures. It is one where failures become precise topology:

- unknown remains unknown;
- unsupported remains unsupported;
- refusal is reproducible;
- blockers preserve their causal type;
- red rails produce bounded repair work;
- repaired defect classes become guards;
- standing never outruns evidence.

That is the falsification discipline required for a software factory that can scale beyond direct human review of every artifact.
